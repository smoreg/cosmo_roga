# E20 — Генератор корабля: дерево, петли, двери, замки и ключи, раскладка, карточки

Статус: done (3 сентября) · Зависит от: E17 · Блокирует: G36, G25, G31 (реальная раскладка) ·
Оценка: 6 ч · Пакет: `packages/engine`

Иначе, чем в задаче: у `Ship` нет полей `keys`/`flagsSet`, поэтому ключи, флаги и карточки отдаёт
`buildShip(spec, rng, ctx): GeneratedShip` (`generateShip` = `buildShip(...).ship`, ключи ещё и
марками `key:k1` в отсеках); раскладка — не барицентрический проход, а два прохода по колонке
(первый ребёнок в строку родителя, второй ниже), чем правило портов выполняется по построению, и
раскладка проверяется на каждом шаге роста, а не после.

## Зачем

Это «генерить карты через либы» из запроса владельца, разобранное по факту (`docs/design-doc.md`,
«Генерация корабля»): импортировать нечего, а словарь и правила стыковки трёх ссылок становятся
данными и инвариантами нашего генератора. Движок получает `generateShip(spec, rng, ctx)` — чистую
функцию от спеки со строковыми типами; что означают типы, марки и карточки — решает игра.

## Что сделать

1. `rooms/gen/shipgen.ts` — `generateShip(spec, rng, ctx): Ship`, алгоритм ровно по GDD:
   1. дерево от `entryKind` (`depth 0`): открытый узел выбирается с весом
      `(3 − children) × (maxDepth − depth + 1)`; тип ребёнка — взвешенно без повторов, пока
      каталог не исчерпан; `required` типы вставляются по одному, `deep` — только на
      `depth ≥ 3` (если дерево не дотянулось — растить дальше до `maxDepth`); `children ≤ 2`;
   2. петли: `15–25 %` от числа рёбер дерева между парами с `|Δdepth| ≤ 1`, у которых ещё есть
      свободный порт на нужной стороне (см. п. 3); `deg ≤ 4`;
   3. `layoutShip(ship)`: `col = depth`, строки — дети под родителем, один барицентрический
      проход; порты: ≤ 2 на сторону, при двух — направления вверх/вниз разные; в колонке ≤ 6;
      экспортируется, чтобы фикстура E17 использовала ту же раскладку;
   4. двери по весам `spec.doors`, затем поправки: `locked` только на рёбрах дерева, `sealed`
      только на петлях; `a1` — `airlock` из `entry` в «никуда» (`b = -1`);
   5. замки и ключи (Дорманс): для каждой `locked` в порядке глубины — ключ `k<n>` в отсеке,
      достижимом от `entry` без этой двери и без не-положенных ключей; ключ записывается в
      `ship.keys` и как марка `key:k<n>` в отсек; места нет → дверь становится `closed`;
   6. карточки: по каждому отсеку `cardsPerRoom` попыток, `cardEligible`/`cardWeight` —
      копии `vaultEligible`/`vaultWeight` из `sim/mapgen/vaults.ts` без размеров; марки карточки
      дописываются в `room.marks`; `sets` → `ship.flagsSet`; марка `lock-entry` запирает дверь
      дерева, ведущую в отсек, по правилу 5 (если это невозможно — марка игнорируется, карточка
      остаётся);
   7. `validateShip` → провал → `rng.fork(attempt)`, до 14 попыток; вернуть лучшую, как
      `buildLevel`.
2. `rooms/gen/validate.ts` — `validateShip(ship, spec): Problem[]` по списку «Гарантии» GDD:
   связность; единственный `airlock` у `entry`; `required` ровно по одному; `deep ≥ 3`; путь к
   каждому `required` без `sealed` и с ключами «по эту сторону» (BFS с множеством собранных
   ключей); достижимость всех отсеков с `breacher`; `locked` только на дереве, `sealed` только на
   петлях; `deg ≤ 4`, порты ≤ 2 на сторону и в разные стороны, колонка ≤ 6, `depth ≤ maxDepth`;
   размер в диапазоне; карточка только в допустимом типе.
3. `rooms/gen/index.ts`, экспорт через `rooms/index.ts`.
4. `assets/CREDITS.md`: строка «словарь отсеков и правило стыковки по портам — по мотивам
   *Starship Geomorphs 2.0* Роберта Пирса (CC BY-NC 4.0); ничего не скопировано». Это
   единственное касание вне `packages/`.

## Тесты (property, 200 сидов × 3 спеки из `dummyship` — маленькая, средняя, «военная» с
`sealed 20 %`)

- `validateShip` пуст на каждом результате.
- Детерминизм: два вызова с одним `rng.fork(i)` — `shipToText` идентичен.
- Ключ каждой запертой двери лежит в отсеке, достижимом без неё; на спеке с `locked 40 %` и
  трёх `required` все три достижимы без `sealed` (прямая проверка BFS с ключами).
- `deg ≤ 4`, порты корректны, колонка ≤ 6 — на всех сидах; раскладка не даёт двух отсеков в одной
  клетке.
- Карточка с `when: () => false` не ставится; `maxPerShip` держится; `lock-entry` запирает дверь
  дерева и кладёт ключ снаружи; `sets` попадают в `flagsSet`.
- Размер в диапазоне; `entryKind` — `depth 0`; `deep` ≥ 3 на 200 сидах, где `maxDepth ≥ 4`.
- Время: 200 × 3 генераций < 5 с.
