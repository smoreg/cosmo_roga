## Зачем

Дверь в v3 — это выбор модуля, оборона и гарантия генератора разом (`docs/design-doc.md`,
«Дверь»). Движок знает состояния и проходимость; игра знает, чем дверь открывают и чем
заваривают, и что каждый способ подставляет под удар.

## Что сделать

1. `systems/doors.ts` — система `DOORS`:
   - `performCommand` для `act` с `verb` из `key | power | spike | cut | weld | close`, `target
     = door.id`, дверь принадлежит отсеку дрона:
     - `key`: `locked` и `player.data.keys > 0` → `open`, ключ −1, шум 0, `The keycard reader
       blinks green. d3 slides open.`;
     - `power`: `locked` и целый CELL → `open`, `cell.integrity −1`, шум 6;
     - `spike`: через `registerHackTarget` риги — `HackTarget { turnsLeft: SPIKE_TURNS, breach:
       () => door.state = "open" }`; шум 4 за ход (рига уже шумит);
     - `cut`: `locked`/`sealed` и целый CUTTER → 3 хода подряд (`room.data.work = { door, left
       }`), шум 9 каждый, экспонирует CUTTER (через `expose` риги с командой) → `broken`;
       любая другая команда сбрасывает работу: `You break off the cut.`;
     - `weld`: `open`/`closed` и целый WELDER → 2 хода подряд, шум 5 → `sealed`;
     - `close`: `open` → `closed`, шум 2.
     Отказ без хода и со строкой почему во всех остальных случаях.
   - `offerActions`: по каждой двери отсека — все доступные методы в порядке тихий → громкий
     (`key`, `power`, `spike`, `cut`; для открытых — `close`, `weld`), `enabled` по наличию
     модуля/ключа, `why` вроде `The terminal needs a spike or a keycard.`
2. Трупы экипажа: `act search {body}` → 3 CR (через `credit` из G26; до G26 — `player.data.loot
   += 3`) и ключ-карта с шансом `keyChance` дереликта (грузовик 30 %); труп с маркой `key:k1`
   отдаёт именно этот ключ всегда. `player.data.keys: number` (ключи не различаются — одно
   число, как в v2; `Door.key` генератора нужен только гарантии «ключ по эту сторону»).
   Обысканный труп пуст навсегда (`room.data.bodies[i].looted`).
3. `panelLines`: `KEYS n` — в блоке заголовка (G37 читает `player.data.keys`).
4. Подсказка-однократка при первом ключе: `A keycard. Doors marked [ ] read it.`

## Тесты

- Каждый метод: меняет состояние ровно так, шумит ровно столько, экспонирует ровно тот модуль;
  прерванная резка/сварка начинается заново.
- `locked` без ключа, CELL, SPIKE и CUTTER — ни одного `enabled` предложения; GHOST перед
  `sealed` — только «обойти» (нет предложений).
- Машина без `breacher` не проходит заваренную дверь; после `cut` — проходит.
- Заваренная/вскрытая дверь остаётся такой после `travelTo` туда-обратно.
- Обысканный труп не даёт ничего второй раз; труп с `key:k1` даёт ключ на 200 сидах всегда.
- `offerActions` на 300 состояниях: `enabled` → `ok`, `!enabled` → отказ без хода.
