# G58 — Две игры в одном процессе портили друг другу забег

Статус: done (проверено и починено 7.09, ветка `task/replay-check`) · Зависит от: — ·
Блокирует: — · Оценка: 2 ч, ушло столько же · Пакет: `packages/engine`

## Вердикт

**Дефект движка, не артефакт снималки.** Прогон роя (G55, «Оговорка к прогону нажатий») видел
настоящее расхождение: 12 885 копий забега разошлись с живым не потому, что харнесс что-то
переиспользовал, а потому что **создание второй игры перенумеровывало сущности первой**.

## Что было сломано

`sim/entity.ts` держал один счётчик идентификаторов на весь процесс:

```ts
let nextId = 1;
export function resetIds(): void { nextId = 1; }
export function makeEntity(init) { return { ...init, id: nextId++, ... }; }
```

Счётчик глобальный по необходимости: `makeEntity` зовут из контента (`content/player.ts`,
`spawnMonsterIn`), а контенту не у кого спросить игру. Но **обнулял** его конструктор — и
`Game`, и `RoomGame` (`resetIds()` первой строкой). Отсюда:

1. Идёт живой забег A. Игрок — `id 1`, машины на борту — `2…k`.
2. Рядом создаётся копия B (реплей по багрепорту, восстановленный сейв, копия харнесса).
   Её конструктор обнуляет счётчик.
3. Забег A вылетает на следующий дереликт, и первая же сгенерированная там машина получает
   `id 1` — тот же, что у игрока.

Дальше расходится всё: порядок хода — по возрастанию `id` (`sim/schedule.ts`), а
`entities.filter(e => e.id !== player.id)` (`stash`, `reapDead`, `visibleMonsters`) начинает
считать машину игроком. Реплей той же последовательности команд в чистом процессе такого не
переживает и приходит в другой мир — что рой и намерил.

Прочие подозреваемые проверены и чисты: `DAMAGE_VETOES` и `HACK_SOURCES` (`twist/rig.ts`)
наполняются на импорте модуля, один раз на процесс; `jumpWarnedAt` (`systems/voyage.ts`) —
`WeakMap` по игре; память «уже сказано» у `systems/contacts.ts` живёт в `currentShip.data`;
язык (`i18n.ts`) в мир не протекает — это отдельный тест ниже.

## Числа

100 сидов, два бота `careful` по 120 команд на игру, сравнение живого забега с
`replayRooms(seed, game.inputs)`:

| Схема | было | стало |
|---|---|---|
| A. Игры чередуются, у каждой свой бот | 100 / 100 разошлись | 0 / 100 |
| B. Игры чередуются, один бот на обе | 2 / 100 | 0 / 100 |
| C. Вторая игра рождается посреди первой | 87 / 100 | 0 / 100 |
| D. Забеги подряд, не чередуясь (контроль) | 0 / 100 | 0 / 100 |

Схема B била реже не потому, что общий бот безопаснее: с испорченной памятью бот почти не
выводит буксир из дока, забег стоит на месте и новых сущностей не создаёт.

## Что сделано

`sim/entity.ts` — счётчик стал принадлежать забегу: `IdSeq`, `newIdSeq()`, `useIds(seq)`.
Счётчик по-прежнему окружающий (иначе контенту его не достать), но каждая игра **забирает**
его себе на входе в то, что может породить сущность, банкуя чужую позицию:

```ts
export function useIds(seq: IdSeq): void {
  if (active === seq) return;
  if (active) active.next = nextId;
  active = seq;
  nextId = seq.next;
}
```

Вызовы — в `RoomGame` и `Game`: конструктор, `playerCommand`, `travelTo`, `leave`/`descend`
(вместо прежнего `resetIds()`). Идемпотентно, так что вложенность (система зовёт `travelTo`
изнутри `playerCommand`) ничего не стоит. `resetIds()` остался для тестов, которые лепят
сущности без игры, и теперь просто выходит из чужой нумерации.

Номера при этом **те же, что были**: каждая игра снова считает с единицы в том же порядке, так
что отпечатки в `tests/replay.test.ts` и фикстуры не сдвинулись — перезаписывать нечего.

## Тест

`games/salvor/tests/determinism.test.ts`, 50 сидов на схему:

- забег реплеится, когда его чередуют с чужим (свой бот у каждого);
- то же, когда вторая игра рождается посреди первой;
- то же, когда обе игры жмёт один бот;
- забег приходит в тот же мир и в те же `inputs`, играли его в одиночку или рядом с чужим;
- мир одинаков на `en`/`ru`/`es` — язык процессный, и если бы перевод протекал в состояние,
  забег, записанный на одном языке, расходился бы на другом. Не протекает.
