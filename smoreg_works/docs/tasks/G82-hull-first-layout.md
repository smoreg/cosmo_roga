# G82 — Корпус первым: соты внутри готового профиля

Статус: done 10.09 · иначе, чем в задаче (после второго и третьего слова владельца через ведущего): маска строится **не из профилей `experiments/hullforms`, а из сот** — `content/hullforms.ts` держит 14 форм как пропорции секций (доля киля, доля высоты в рядах), корпус выкладывается симметрично относительно киля (сота `(q, r)` ↔ `(q + r, −r)`, тест на всех формах и размерах), толщина берётся от собственной деки корабля (`hexThickness`, не выше рамки), длина растёт, пока сот не станет ≥ отсеков + 20 %, а раскладка не примет маску; рисунок повторяет маску — прямоугольники секций со скосами на уступах и носом, дырка станции, тела состава; всё, что рисует корпус, обрезано силуэтом (один `clipPath` на слой: тела + гондолы − дырки), обшивка режется по пролётам самого контура, мачты убраны (диагональ на кадре владельца была мачтой), люки/иллюминаторы/рубка ставятся только там, где целиком внутри; в `hexLayout` при маске третье слагаемое — близость к центру маски, `hexFit` кладёт собственные соты генератора ближе к центру; приёмка кадра владельца: непокрытая сотами площадь ≤ 35 %, толщина тела ≥ 1.5R везде до последней соты, ни одна точка примитива не вне силуэта (37 тыс. точек на 200 кораблях), медианная занятость 71 %, симметрия 200/200, маска принята 198/200, коридоров 97.8 %; карантин на 14 отсеков — отдельной тройкой на листе (было / стало / `?hull=0`); движок: `hexLayout(ship, { allowed })` + `masked`, изометрии, строгий и мягкий поиск с откатами, обмен сот в `repair`, экспорт `hexKey`, `hexFit`, `hexThickness`, `MASK_FLOOR`, `HexLayoutOptions`; бюджет рамки «≤ 8R × 3R роста» заменён на «w ≤ 1718, h ≤ 764 где влезала голая, сота на экране ≥ 75 % от голой»; раскладка и подгонка кэшируются по объекту корабля; буксир отца: голова в семь рядов держит его 25 отсеков, часть сидов — с чипами (порог 0.8 соблюдён)

Владелец, 9.09, глядя на G81 на проде: «чет пятна, го возьмём пре-генеренные корпуса, а внутри них
данж». То есть порядок переворачивается: сначала **готовый профиль корабля**, потом соты **внутри
него**, а не обвод, сшитый из граней случайно выросшей решётки.

Почему сегодня пятна: `hexLayout` растит решётку жадно от графа, форма получается какая вышла, и
G81 обводит её по краю. Отсюда рваный многоугольник, гондолы «где-то сбоку» и соты, не заполняющие
корпус (скриншот владельца: баржа `HALLOWAY`, 10 отсеков, половина корпуса пустая).

## Решение
**Маска решает, куда расти.** Профиль корабля выбирается по классу и сиду, масштабируется под число
отсеков, из него берётся список разрешённых сот, и раскладка растит дерево **только внутри** этого
списка. Корпус рисуется из **самого профиля** (прямые борта, гондолы у кормы, нос, рубка), а не из
граней сот.

**Граф не трогается.** `generateShip` остаётся как есть, значит баланс, фикстуры, реплеи и боты — как
есть. Меняется только раскладка (что где нарисовано) и рисунок.

## Работа
1. **Профили в TS.** `games/salvor/src/content/hullforms.ts` — порт `experiments/hullforms/shipform.mjs`:
   `SIZES`, `CLASSES` (20 классов: тела как `[длина, полувысота сверху, снизу]`, `bodies` со сдвигом
   и `holes`), `shipForm(kind, seed, R, scale)`, `cellsInside(form)`, `fitScale(kind, seed, R)`.
   Данные, без DOM, без `Math.random()` — сид приходит параметром.
2. **Маска в раскладке.** `packages/engine/src/rooms/gen/hexlayout.ts`:
   `hexLayout(ship, opts?: { allowed?: ReadonlySet<string> })` — где `allowed` это набор ключей
   `hexKey`. Рост идёт только по разрешённым сотам; сортировка кандидатов прежняя (`breathing`,
   `loopsMet`), плюс `repair()` в тех же границах. Движок ни слова об игре не знает: это набор
   координат, не «корабль».
   **Гарантия отката:** если внутри маски дерево не размещается целиком (или доля коридоров падает
   ниже 0.8), функция возвращает раскладку **без маски**, как сегодня, и помечает результат
   (`masked: false`). Ни один корабль не остаётся без карты.
3. **Выбор профиля.** `content/hulls-art.ts`: класс дереликта → профиль (уже есть 12 строк), плюс
   выбор масштаба: наименьший, при котором `cellsInside` даёт **≥ отсеков + 30 %** запаса (запас
   нужен, чтобы дерево не заперлось). Всё детерминировано от `shipId`.
4. **Рисунок из профиля.** `ui/web/hullart.ts`: контур берётся из `form` (прямые секции), а не из
   `outlineLoops` по сотам; обшивка, гондолы, нос, рубка и мачты ставятся по геометрии профиля
   (как в `experiments/hullforms/hullart.mjs` и `shipform.mjs:renderShip`). Обвод по сотам остаётся
   **только** как запасной путь для `masked: false`.
5. **Точка вызова.** `ui/web/screen.ts:136` — `hexLayout(game.ship)` получает маску:
   `hexLayout(game.ship, { allowed: cellsOf(art) })`, где `art` уже вычисляется рядом. `?hull=0`
   по-прежнему выключает и корпус, и маску (байт в байт сегодняшняя раскладка).

## Тесты
1. Инварианты движка на месте: каждый отсек в своей соте, коридор только между касающимися,
   каждая дверь нарисована или названа, чистая функция от графа (существующие тесты
   `packages/engine/tests/hexlayout.test.ts` не ослаблять).
2. С маской на 200 сгенерированных кораблях: все соты внутри профиля; доля коридоров ≥ 0.8;
   `masked: true` не реже чем на 90 % кораблей (иначе маска бесполезна — крутить запас из п. 3).
3. Откат: корабль, которому маска мала, раскладывается без неё и рисуется обводом; тест на
   искусственно тесном профиле.
4. Рисунок: борта прямые (в контуре нет отрезков короче 0.5R под углами, не кратными секциям),
   каждая сота внутри обшивки, гондолы у кормы, нос и рубка на носу.
5. Рамка: `viewBox` не выходит за 1718×764 сильнее, чем сегодня (бюджет G81: ≤ 8R по ширине,
   ≤ 3R по высоте).
6. `?hull=0` — байт в байт сегодняшний SVG (золотой файл G81).
7. Детерминизм: два вызова и два одинаковых сида — одинаковая строка.

## Баланс
Граф не меняется → правил не касается. Один прогон `balance`+`winnable` для формальности, фикстуры
**не** перезаписывать. Если что-то в них поехало — значит тронут граф, это ошибка, а не новая норма.
