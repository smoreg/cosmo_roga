# ADR 0001 — Стек: TypeScript + rot.js + Vite

Дата: 2026-08-25 · Статус: **принято окончательно** (подтверждено владельцем 2026-08-25 после разбора движков-конкурентов)

## Контекст

Джем на 14 дней, критерии — Fun, Robustness, Innovation, Traditional Roguelike. Из разведки
Fortnight 1: у игры-победителя было **5 оценок**. В таком джеме доступность решает: если игру
надо скачать и разархивировать, часть голосующих просто не дойдёт до запуска.

Рассматривались:

| Вариант | За | Против |
|---|---|---|
| **TypeScript + rot.js + Vite** | нативный веб, бандл ~70 КБ, rot.js даёт FOV / pathfinding / генерацию карт / Display, мгновенный HMR, тесты в vitest без браузера | rot.js не развивается (последний релиз — ноябрь 2024) |
| Go + gruid + gruid-js (WASM) | родной язык, сильная типизация, `rl`-пакет с FOV и генерацией | WASM-бандл на порядок толще, отладка в браузере хуже, gruid-js менее протоптан |
| Python + tcod | самая протоптанная дорога в жанре, лучший туториал | нет нормального веб-билда → скачиваемый архив → меньше голосов |
| Godot 4 | веб-экспорт из коробки | сеточная пошаговая логика в Godot — работа против движка; экспорт весит десятки МБ |

## Решение

TypeScript + rot.js 2.2.1 + Vite.

Причины в порядке веса:

1. **Играется в браузере в один клик.** Прямо влияет на число оценок.
2. **Robustness — оцениваемый критерий.** Вся симуляция в `src/sim/` не знает про DOM, значит
   тестируется в vitest: инварианты карты, детерминизм, отсутствие коллизий. 24 теста уже есть.
3. **Скорость итерации.** HMR-цикл в секунду против пересборки WASM.
4. То, что rot.js «не развивается», для двухнедельного джема не риск: библиотека
   feature-complete, без зависимостей, и используется только как набор алгоритмов.

## Вопрос закрыт

Решение перепроверено дважды и больше не пересматривается:

- разбор работ прошлого джема — **вся первая пятёрка играется в браузере**, при этом
  движки у них все разные (Godot, Godot, C+libtcod, Lua+LÖVE, TIC-80). Значит решает
  не движок, а веб-сборка (`docs/prior-entries.md`);
- разбор исходников prism и libtcod — заимствовать оттуда стоило два приёма, а не
  стек: и то и другое требует Lua/LÖVE или C с emscripten (`docs/engine-study.md`).

Внутри джема стек не меняется ни при каких обстоятельствах — см. `docs/scope-rules.md`.

## Следствия

- `src/sim/` не импортирует ничего из `src/ui/`. Обратное — можно. Это правило держит
  тестируемость и его нельзя нарушать «на один раз».
- Своя `Rng` (mulberry32) вместо `ROT.RNG` — состояние это одно целое число, значит забег
  сериализуется, а `?seed=N` в URL воспроизводит его точно. `ROT.RNG` засевается из нашего
  потока только перед вызовом генератора карт.
- Не используем `ROT.Engine` и `ROT.Scheduler`: свой энергетический планировщик в
  `sim/schedule.ts` детерминирован и не завязан на колбэки и блокировки.
- Рендер через `ROT.Display` в режиме `rect` (ASCII). Если появится время — тайлсет
  подключается сменой `layout` на `tile` без изменений в `sim/`.
