## Протокол работы (как было — работает)

- Один агент = одна задача = свой worktree `git worktree add -b task/<x> ~/code/my/jamrog-wt/<x> main`,
  первым действием `npm install` в worktree. Непересекающиеся файлы, `git add <явные пути>`,
  коммиты без упоминания AI, без пуша.
- Бриф: цель, файлы владения, «НЕ трогать», тесты обязательны, гейт `npm test` +
  `npm run typecheck` + `npm run build` с точными числами, отчёт ≤ 30 строк в нумерованном виде.
- **Гейт на слитом `main` до снятия агента** (урок: G37+G14 по отдельности зелёные, вместе 9
  красных). Мержить в основном репо: `git -C /Users/smoreg/code/my/jamrog merge task/<x>`;
  **cwd в Bash персистит** — после `cd games/salvor` `npm test` падает «Missing script» (это не
  поломка, а cwd). После мержа — `git worktree remove ~/code/my/jamrog-wt/<x>`, ветку оставить.
- Браузер не для проверок (правило владельца, `docs/tasks/README.md` п. 9) — только vitest и боты.
- **Worktree живого агента не снимать.** 7.09 снял `objective` сразу после его отчёта — агент был
  жив, получил новое поручение, и вместе с worktree потерял 11 незакоммиченных файлов; переписывал
  заново. Снимать только после того, как агент отчитался **и** ветка влита, и лучше без `--force`:
  отказ «contains modified files» — это сигнал, что работа не закоммичена, а не помеха.
- Агентам в брифе: **коммитить незаконченное** при первом же удобном случае. Падения по лимиту API
  («all accounts exhausted») случаются пачками и не по вине агента; закоммиченное переживает их.
- Потолок 4 агента одновременно (лимиты API: за сессию были 529/500 и «all accounts exhausted»);
  упавшего поднимать `SendMessage` «продолжай с места, ничего не переделывай», не пересоздавать.
- Модели: opus для задач с решениями, sonnet для механики; fable — только по слову владельца.
- Балансовые агенты: границы файлов задавать явно — balance-2 не смог тронуть ни одного числа,
  потому что литералы прочности стоят в `tests/{rig,panel,actions,salvage}.test.ts`, а страховка
  покрытия — в `tests/persistence.test.ts`; balance-3 получил их в собственность и взял победу.
- Фикстуры `tests/fixtures/voyage-*.json` пишутся живым ботом: **любое** изменение, которое меняет
  решения бота (число контента, строка действия, правило бота), требует `RECORD=1`. Два агента,
  перезаписавшие их параллельно, конфликтуют по всем трём файлам — разрешать так: первый в `main`,
  второй мержит `main` к себе, берёт любую сторону и перезаписывает заново на слитом дереве.
- Деплой: rsync один раз завис после доставки файлов (ssh-сессия не закрылась) — проверять
  результат по имени бандла в HTML прода, а не по коду выхода rsync.

## Рецепт деплоя

```bash
npm test && npm run typecheck
(cd games/salvor && npx vite build --base=/salvor/)
rsync -a --delete games/salvor/dist/ root@smoreg.dev:/var/www/salvor/
curl -sS -o /dev/null -w "%{http_code}\n" https://smoreg.dev/salvor/
```
Nginx трогать не надо (сниппет и include стоят). Карта прода: `~/code/_projects_map/server.md`.

**Проверять деплой только так** (7.09 научен: rsync упал с «unexpected end of file», имя бандла в
HTML совпадало, а самого файла на сервере не было — страница отдавала 200 и белый экран):

```bash
JS=$(curl -sS https://smoreg.dev/salvor/ | grep -o 'assets/index-[A-Za-z0-9_-]*\.js' | head -1)
curl -sS -o /dev/null -w "bundle %{http_code} size %{size_download}\n" "https://smoreg.dev/salvor/$JS"
```

Размер обязан быть сотнями килобайт. Совпадение имени ничего не доказывает: при отсутствии файла
nginx отдаёт index.html с кодом 200, и «проверка» проходит.
