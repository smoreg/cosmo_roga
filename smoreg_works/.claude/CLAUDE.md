# jamrog — правила репозитория

Монорепо: движок для traditional roguelike + игры на нём.
Первая игра — заявка на [roguetemple's Fortnight 2](https://itch.io/jam/roguetemples-fortnight-2),
**1–15 сентября 2026**.

Перед работой: **`docs/design-doc.md`** (что делаем — SALVOR, зафиксировано 3 сентября),
**`docs/tasks/README.md`** (задачи для агентов и протокол), `docs/jam-brief.md` (правила и
критерии джема), `docs/plan-14-days.md`
(на каком мы дне), `docs/cookbook.md` (что уже есть в движке — почти всё).

## Структура и границы

```
packages/engine/     @jamrog/engine — ядро, ничего не знает об играх
packages/audio/      @jamrog/audio  — адаптивная музыка и звук (DOM, без sim)
games/_template/     скелет новой игры (вне воркспейса)
games/fortnight2/    заявка на джем: src/content, src/ui, music/, assets/, tests/
assets/              общие ассеты: fonts / tiles / audio + CREDITS.md
scripts/new-game.mjs npm run new-game -- <id> "Название"
```

Границы жёсткие, нарушать нельзя:

1. **`packages/` не импортирует из `games/`.** Никогда. Движок получает игру как
   `ContentPack` (`packages/engine/src/content/kinds.ts`).
2. **Игра импортирует только `@jamrog/engine` и `@jamrog/engine/testing`**, не пути
   внутрь пакета. Иначе перестановка файлов в движке ломает игры.
3. **`src/content/` не импортирует `src/ui/`.** Контент не знает про рендер.
4. **`sim/` не знает про DOM.** Ни одного `document`, `window`, `Audio`.
5. **Никакого `Math.random()` и `Date.now()` в `sim/`.** Только `game.rng` — на этом
   стоят воспроизводимость забегов, багрепорты через `?seed=N` и половина тестов.

Новую игру создавать генератором, не копированием руками:
`npm run new-game -- mygame "My Game"`, затем `npm install`.

## Жёсткие ограничения джема (для игры fortnight2)

1. **Никакой мета-прогрессии.** Между забегами не переносится ничего. `localStorage` —
   настройки и **приостановленный текущий забег**, никогда результаты прошлых.
   Сейв — это `(seed, inputs)` и ничего больше (`ui/react/suspend.ts`): тот же
   механизм, на котором стоит `replayRooms`, руками не подделать, и он стирается
   в тот момент, когда забег кончается. Закрыть вкладку посреди вылазки и
   вернуться в неё — это тот же забег, а не перенесённый прогресс.
2. **Пошаговость.** Мир двигается только через `Game.playerCommand()`.
3. **Permadeath.** Нет undo, нет откатов хода.
4. **PCG должна что-то решать.** Заменяемая рукодельным уровнем генерация = провал по
   четвёртому критерию.
5. **До 1 сентября — только каркас.** Правила разрешают переиспользуемый код заранее,
   но не игровой контент.

## Кирпичи — сначала посмотреть, что уже есть

Полная карта и рецепты: **`docs/cookbook.md`** — две таблицы кирпичей, по одной на мир.

**Игра джема живёт в корабельном мире** (`rooms/`: отсеки — узлы, двери — рёбра):

- пути, погоня, бегство, авто-исследование → `RoomDistance` (`rooms/paths.ts`), **не** новый A*
- новый корабль → `ShipSpec` + карточки отсеков, **не** свой генератор
- характер машины → профиль в `rooms/behaviours.ts`, **не** конечный автомат
- шум и видимость через двери → `rooms/noise.ts`, `rooms/sight.ts`
- тест на любую ситуацию → `shipFromText` (`testing/roomfixtures.ts`), рисуется текстом
- боты и метрики → `roomPlay` + `runBotOn` (`testing/roombots.ts`)
- механика поверх цикла хода → система в списке `systems` (`sim/twist.ts`) — общий для обоих миров
- урон/лечение/статус → `sim/effects.ts` как данные — тоже общий

**Ловушка экспорта:** сетка заняла имена первой, поэтому корабельные выходят из
`@jamrog/engine` с приставкой (`roomDesireDriven`, `ROOM_BEHAVIOURS`, `performRoom`,
`randomRoomBot`). `import { desireDriven }` молча даёт сеточное поведение.

Сеточные кирпичи (`sim/dijkstra.ts`, `sim/shadowcast.ts`, `sim/mapgen/`, `testing/fixtures.ts`)
— только для `games/fortnight2`, которую никто не трогает.

Музыка и звук → `@jamrog/audio` + скилл `composing-music`; правила проекта в
`games/fortnight2/music/README.md`.

## Инварианты под тестами (2182 теста, не ломать молча)

- **FOV симметричен ровно на 100 %** (см. `docs/adr/0002-symmetric-fov.md`)
- Каждый проходимый тайл достижим от входа; лестница достижима — для всех четырёх
  генераторов, 200 сидов × 8 глубин
- Внешняя граница карты всегда сплошная стена
- Генерация — чистая функция от `(seed, depth)`
- Две блокирующие сущности никогда не занимают один тайл
- Нелегальный ход не тратит ход игрока
- Игрок никогда не оказывается в стене
- Поведение ИИ никогда не даёт шаг в стену и никогда дальше одной клетки
- `replay(seed, inputs, { content })` — бит-в-бит тот же результат
- Испорченный сейв не роняет игру
- Умение играть лучше даёт большую глубину (`games/*/tests/balance.test.ts`)
- Кроссфейд музыки сохраняет мощность; переход всегда попадает на границу такта

Правил `sim/` коснулся — `npm test` до слова «готово».

**Игру в браузере не тестировать.** Браузер — только вью; проверка — vitest, боты, фикстуры,
чистые функции UI. Скриншоты и ручные забеги делает владелец сам.

## Команды

```bash
npm install                       # связать воркспейсы (после new-game — обязательно)
npm run dev                       # игра для джема
npm test                          # все тесты монорепо
npm run typecheck
npm run build                     # сборка игры для джема
npm run zip -w games/fortnight2   # dist + zip для itch.io
npm run new-game -- <id> "Имя"    # новая игра из шаблона

node tools/deck/bake.mjs          # из games/salvor: палубная графика в public/deck
node tools/audio/copy.mjs        # из games/salvor: музыка в public/audio
node tools/machines/fetch.mjs    # из games/salvor: иконки машин и дрона (сеть)
node tools/sfx/bake.mjs          # из games/salvor: семь эффектов в public/audio/sfx
npm run zip -w games/salvor      # dist + проверка + derelict-rogue-web.zip
npm run publish:itch -w games/salvor   # то же + butler push на itch
```

**Куда публикуется:** <https://vuvko.itch.io/derelict-rogue-14drl>, канал `html5`.
Старый адрес `/derelict-rogue` отдаёт 302 на этот — браузер по нему пройдёт, а
API butler'а нет: `butler push vuvko/derelict-rogue:html5` падает с «invalid
game». Цель — всегда полный slug.
`butler push` отправляет папку `dist`, а не zip: butler считает разницу, и
следующая заливка везёт только изменившееся. Zip остаётся для ручной загрузки
через форму. Перед заливкой отрабатывает `tools/itch/check.mjs`: все ссылки в
html относительные и на месте, все плитки из манифеста существуют, музыка есть,
оба уведомления о лицензиях едут внутри сборки.

**Палуба под отсеками — сборка, а не содержимое репозитория.** `public/deck/`
в `.gitignore`: 11 МБ чужой графики под **CC BY-NC**, взятой из скачанного
набора в `vuvko_works`. Без неё доска рисуется плоской — это ровно то, что
было до плитки, и это по-прежнему целая игра. Всё, что собрано с этими
плитками, остаётся некоммерческим (`games/salvor/public/deck/LICENCE.md`).

**Музыка — тоже сборка.** Шесть треков, 23 МБ, уже лежат в этом репозитории
один раз — в `vuvko_works/game/public/audio/music`, — поэтому вторая копия под
`smoreg_works` не коммитится: её кладёт `tools/audio/copy.mjs`. Пять треков
Eric Matyas (soundimage.org) требуют указания авторства везде, где появляется
игра; шестой — «Soft Millenium» 3D63 — по личному разрешению автора на том же
условии. Уведомление едет вместе с файлами
(`games/salvor/public/audio/ATTRIBUTION.md`) и стоит на экране титров. **Условия
Matyas со временем менялись — перечитать перед релизом.**

## Два известных пробела игры (найдены тестами; решения — в GDD: модули и тревога, задачи G2/G6)

1. **Нет восстановления HP** — 20 HP на 8 уровней непроходимы арифметически.
2. **Нет давления времени** — бесконечный кайтинг легален и локально оптимален.

Не «чинить» правкой тестов: это дизайн-задачи джема. Когда решены — ужесточить пороги
в `balance.test.ts` и `winnable.test.ts`.

## Как добавить контент

Слои и рецепты — **`docs/adr/0003-decoupling.md`**. Коротко: враг — строка в
`content/monsters.ts` плюс `id` в `band` классов; отсек — строка в `content/zones.ts` плюс
`kind` в `kinds` классов; сценарий (класс корабля) — строка в `content/derelicts.ts`; что
где лежит — карта в `content/cards.ts`. Ни один из четырёх шагов не требует кода.

Забытая вторая таблица ловится `games/salvor/tests/content.test.ts` — не глазами.

Правило слоёв: **запись состояния не живёт в файле с механикой, которая её меняет, если
её читает кто-то ещё** (`systems/shipstate.ts`, `systems/rivalstate.ts`, `systems/purse.ts`,
`ui/strikers.ts`). Цикл импортов — не стилистика, а отложенный краш: под ESM модуль с
регистрацией на верхнем уровне падает с `is not a function`, как только цикл замкнётся ещё
одним ребром. Один цикл оставлен сознательно и объяснён в ADR; новых не заводить.

Штаммы вируса — таблица `content/viruses.ts`: штамм это данные, вид вреда это код.

## Чего не делать

`docs/scope-rules.md`. Коротко: магазины, экран инвентаря, своя ECS, свой генератор карт,
диалоги, звук до дня 9, смена стека (закрыто в `docs/adr/0001-stack.md`).
После дня 13 — фиче-фриз, только починка багов.
